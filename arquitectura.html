Arquitectura de Docker

Docker utiliza una arquitectura cliente-servidor. Las instrucciones del usuario son enviadas por un cliente al servicio encargado de administrar los recursos de Docker. Esta organización permite construir imágenes, ejecutar contenedores y gestionar redes y volúmenes desde una terminal o desde otras aplicaciones.

Modelo cliente-servidor

La arquitectura está formada principalmente por Docker Client, Docker Daemon y Docker Engine API. Además, utiliza registros (registries) para almacenar y distribuir imágenes.

Componentes del modelo cliente-servidor
Componente Función
Docker Client Interfaz con la que el usuario envía instrucciones, normalmente mediante el comando docker.
Docker Daemon (dockerd) Servicio que recibe solicitudes y administra imágenes, contenedores, redes y volúmenes.
Docker Engine API Interfaz mediante la cual el cliente y otras aplicaciones se comunican con el daemon.
Docker Registry Servicio que almacena imágenes para descargarlas o publicarlas. Docker Hub es un registro público muy utilizado.

Importante: el cliente y el daemon pueden ejecutarse en el mismo equipo o comunicarse de forma remota. Esto permite administrar un daemon ubicado en otro sistema.

Componentes principales

Docker Client

Es el medio principal de interacción con Docker. Cuando el usuario escribe una instrucción, como docker run, el cliente envía la solicitud al daemon mediante la API. El cliente no realiza por sí solo todas las tareas de creación y ejecución; solicita al daemon que las lleve a cabo.

Docker Daemon

El daemon, identificado normalmente como dockerd, permanece en ejecución esperando solicitudes. Se encarga de construir imágenes, crear y administrar contenedores, configurar redes y gestionar volúmenes.

Docker Engine API

Es una API de tipo REST que establece cómo los programas pueden enviar instrucciones al daemon. La CLI de Docker utiliza esta API, pero otras aplicaciones también pueden utilizarla para automatizar operaciones.

Docker Registry

Es un servicio donde se almacenan imágenes de Docker. Cuando una imagen no está disponible localmente, Docker puede descargarla desde un registro. También permite publicar imágenes propias para compartirlas con otros equipos o entornos.

¿Cómo funciona una operación de Docker?

Al ejecutar un comando para iniciar un contenedor, se produce una secuencia de comunicación entre los componentes:

  1. El usuario escribe una instrucción en Docker Client, por ejemplo: docker run nginx.
  2. El cliente envía la solicitud al Docker Daemon mediante la Docker Engine API.
  3. El daemon comprueba si la imagen solicitada está disponible localmente.
  4. Si la imagen no está disponible, el daemon puede descargarla desde un registro, como Docker Hub.
  5. Con la imagen disponible, el daemon crea y pone en ejecución el contenedor.
  6. El resultado de la operación se comunica al cliente, que muestra información al usuario.

Ejemplo: al ejecutar docker run nginx, Docker busca la imagen nginx, la descarga si hace falta y crea un contenedor para ejecutar el servidor web.

Flujo general de trabajo

Etapas del flujo de trabajo de Docker
Etapa Qué sucede
Construcción Se prepara un Dockerfile y se construye una imagen con docker build.
Almacenamiento La imagen queda disponible localmente o se publica en un registro con docker push.
Descarga Otro equipo puede obtenerla desde un registro mediante docker pull.
Ejecución Se crea un contenedor a partir de la imagen mediante docker run.
Administración Se consultan, detienen, reinician o eliminan contenedores según sea necesario.
